## Minimum coherent architecture
Single same-origin modular application with public catalogue/detail/contact, authenticated inventory/inquiry administration, repository/service boundaries, versioned schema/migrations and SQLite for isolated local low-write workload. This is a local choice, not final production DB approval. No microservices or payment implementation unless live baseline actually proves it necessary and user scope covers it.

Entities: Product(stable source ID/title/description/price/currency/status/category/reference/source snapshot); Category; Media(source URL/original hash/rights disposition/order/alt/product); Inquiry(product ID optional/snapshot of item reference/name/contact/message/status/time); Admin; expiring revocable Session; Audit; local NotificationOutbox. Keep code, DB, media/private attachments and backups separate. Inquiry state plus outbox should commit atomically; production transport disabled and not configured by this task. Local receipt means saved for review, never emailed or delivered.

Admin initial credential outside repo/logs, no default shared password. Prefer established available auth/session/validation libraries, secure password hashing, HttpOnly SameSite cookies, CSRF+Origin protection, login throttling, logout/session expiry/revocation. Loopback HTTP cookie exception only for local mode; fail closed in production config. One administrator role is sufficient if sole-operator assumption explicit; do not build fake unused roles. No public file upload needed absent baseline requirement. Admin media ingestion still needs strict MIME/size/path checks and rights metadata.
